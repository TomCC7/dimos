Why this change

Current Piper teleop recording writes pickle-per-frame directories. The change moves collection to per-episode Rerun .rrd files so each episode is a direct training/review artifact, aligned with Rerun 0.32 dataset tooling and dataloader semantics.

Core intent: keep live viewer and on-disk recording independent while preserving converter parity and entity-path consistency.

Decision highlights

  • Recorder is a standalone module; bridge remains live-viewer only.
  • Bridge file is intentionally left untouched; recorder duplicates small composition logic locally.
  • Episode rollover is explicit RPC plus Quest-button boundary module.
  • Viewer throttling must not affect recorder throughput.

Entity schema

  • /observation/camera/usb
  • /observation/state/<joint_short_name>
  • /action/<joint_short_name>
  • /meta/episode_id, /meta/episode_index, /meta/session_id, optional /meta/operator

Requirements (normative)

Per-episode recording:

The blueprint SHALL write each demonstration episode to its own .rrd at {data_dir}/piper_data_collection/<session_name>/episode_<NNN>.rrd; session defaults to UTC YYYYMMDDTHHMMSSZ; episode counter is 1-indexed and zero-padded.

Episode rollover:

WHEN rollover button is pressed, recorder SHALL close current file and open next file; messages after boundary SHALL log only to the new episode.

Debounce and empty-file behavior:

WHEN events occur within 500ms, they SHALL be ignored and no extra empty file produced. WHEN rollover occurs before payload data, current episode file SHALL be removed.

Metadata:

Each episode SHALL include static metadata entities for episode ID, episode index, and session ID; operator metadata is present only WHEN configured.

Module independence:

Viewer and recorder SHALL be separate modules with independent streams/sinks. Viewer failures must not stop recording; recorder failures must not stop viewer operation.

Risks and trade-offs

Trade-offs accepted

  • No in-tree pickle→rrd migration.
  • No in-tree training example or catalog server in this change.
  • Raw image logging now; post-session rerun rrd optimize remains documented step.

Operational concerns

  • Rollover correctness under in-flight messages requires lock-safe close/open boundaries.
  • Recorder and bridge converter logic can drift; tests are specified to catch divergence.
