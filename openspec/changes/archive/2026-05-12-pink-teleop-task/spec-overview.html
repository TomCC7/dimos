Why

Move IK problem construction into Pink

DimOS teleop currently uses a lightweight Pinocchio IK path. Pink provides task-based differential IK with weighted frame tasks and a QP solver loop, giving a stronger base for robot-specific IK tasks.

First milestone

XArm7 only

The implementation starts with XArm7IKTask. It consumes only the right controller pose and keeps the current teleop_xarm routing contract.

Not yet

Dual arm deferred

Dual-arm coordinated IK remains the motivation, but it is deferred to a later subclass because combined robot models and multi-target routing need robot-specific construction.

Architecture

Hierarchical task design

BasePinkIKTaskXArm7IKTaskfuture subclasses

  • BasePinkIKTask owns shared solver setup, current-joint extraction, target-update hooks, joint-delta safety, and output generation.
  • SingleFramePinkIKTask owns single end-effector target state, timeout handling, and baseline capture.
  • XArm7IKTask owns XArm7 model loading, end-effector frame task construction, right-controller target updates, and XArm7 resource claims.
  • Future subclasses can add XArm6, Piper, or dual-arm combined-model construction without overloading the first task.
Controller contract

Delta, not absolute pose

  • PoseStamped.position and orientation are robot-frame controller deltas from engagement.
  • The XArm7 task captures the current end-effector pose as its baseline on right-controller engage.
  • The Pink frame target is baseline plus controller delta.
  • Disengage/re-engage clears and recaptures the baseline.
Requirements

What must be true

1
Shared Pink IK base
Uses coordinator timing, emits coordinator-compatible commands, and rejects unsafe joint deltas.
2
XArm7-specific Pink task
Loads XArm7 model, validates joint/frame configuration, and owns XArm7 resources.
3
Right-controller-only input
Keeps teleop_xarm compatibility and does not require left-controller data.
4
Safe stale-state behavior
Missing joints, timeout, or solver failure produce no command rather than unsafe motion.
5
Explicit Pink dependency
Adds pin-pink and a deterministic QP solver path.

Key decision

Do not generalize too early

The first implementation is intentionally narrow: XArm7, right controller, one Pink FrameTask, existing route key. The base class captures only proven shared behavior so future robot-specific tasks can extend it without forcing dual-arm complexity into the first milestone.
